# Architecture Decision Records (ADR)

각 ADR은 한 번 결정한 후 변경 시 새 ADR을 추가(supersede)한다. 기존 ADR은 수정하지 않는다.

## 목록

| # | 제목 | 상태 | 날짜 |
| --- | --- | --- | --- |
| 0001 | 데스크톱 앱 셸로 Tauri 2.0 채택 | Accepted | 2026-04-30 |
| 0002 | Win 우선 개발 + Mac CI/클라우드 검증 | Accepted | 2026-04-30 |
| 0003 | 오픈소스 범위 (예정) | Pending | Week 6 후 |

## 템플릿

```markdown
# ADR-NNNN: 제목

- 상태: Proposed / Accepted / Superseded by ADR-XXXX
- 날짜: YYYY-MM-DD
- 결정자: @누구

## 맥락
무엇이 문제인가, 왜 결정이 필요한가

## 결정
무엇을 결정했나

## 대안
- 옵션 A — 장단
- 옵션 B — 장단

## 결과
- 좋은 점
- 나쁜 점 / 트레이드오프
- 후속 액션
```
