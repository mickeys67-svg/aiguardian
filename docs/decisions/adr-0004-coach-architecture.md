# ADR-0004: 코치 동반자 — 스탠스·조언 모델·통합 아키텍처

- 상태: Accepted
- 날짜: 2026-06-08
- 결정자: @seungho
- 관련: ADR-0001(Tauri), v0.3 MCP-first 재설계

## 맥락

v0.9 설계로 만든 현재 데스크톱 앱을 직접 테스트했을 때 "이게 바이브코딩을 돕는 건지 모르겠다"는 문제가 드러났다. 대규모 코드 분석 결과, 근본 원인은 **기능 부족이 아니라 스탠스**였다.

1. **앱이 "app-as-executor"다.** `install_tool`의 `winget --silent`, `run_recipe_step`의 `cmd /S /C` 직접 실행처럼, 앱이 명령을 *대신 몰래 실행*해 터미널·셸·명령을 숨긴다. 입문자는 아무것도 배우지 못한다. "버튼 누르면 뚝딱"은 바이브코딩 코치가 아니라 자동화 머신이다.
2. **우리는 IDE도, 채팅 AI도, 터미널도 아니다.** 코드를 쓰는 건 AI, 편집은 IDE, 실행은 셸이 한다. 그 사이에 정체성을 잡아야 한다.
3. **여러 AI 클라이언트와 호환되어야 한다.** Claude Code 하나에만 붙으면 "그냥 플러그인"이다. 무엇을 토대로 삼아야 Claude Code·Cursor·Claude Desktop 등에 두루 붙는지 결정이 필요하다 (2026-06-08 생태계 조사 수행).

## 결정

### 1) 스탠스 — "user-runs, app-coaches"

앱이 대신 실행하지 않는다. **사용자가 직접 하되, 우리가 옆에서 플로우의 빈칸을 가르쳐 채운다.** 채울 빈칸: AI가 시킨 명령을 ①어느 터미널에 ②어떤 셸(PowerShell/bash)로 ③코드는 어느 파일·폴더에 ④에러 해석 ⑤다음 방향.

### 2) 핵심 기능 — 두 가지 조언 모드

- **능동 조언(turn-between):** AI가 한 개발 턴(프롬프트→개발)을 끝낸 순간, 입문자에게 5버킷 코칭(무슨 일/확인할 것/직접 할 일/놓친 것/다음 방향)을 준다.
- **수동 조언(on-demand):** 사용자/모델이 명시적으로 부르는 코칭(리뷰·체크).

조언은 **사람에게만** 간다. AI를 떠밀어 코드를 더 생성하게 하는 채널(`additionalContext`)은 쓰지 않는다 — 이것이 코치와 자동화 머신을 가르는 선이다.

### 3) 통합 아키텍처 — 단일 코어 + 어댑터 + 2모드

조사 결과: **MCP는 유일한 크로스클라이언트 표준이나 수동(request-response)이며 서버가 먼저 말 걸기·턴종료 감지가 불가**(Claude Code "not planned"). **턴경계 훅이 되는 곳은 Claude Code·Cursor(베타)·Windsurf 3곳뿐.** sampling/elicitation은 주요 클라 미구현이라 베팅 불가.

→ **둘 다, 계층으로:**

- **단일 코칭 코어** (클라이언트 독립, turn분석→조언, 규칙 기반). 자체 API 키 불필요.
- **능동 조언 = 클라별 훅 어댑터** (Claude Code `Stop`·`systemMessage`, Cursor `stop`·`user_message`, Windsurf `post_cascade`). 각 어댑터가 공통 로컬 엔드포인트로 입력을 정규화해 코어에 전달.
- **수동 조언 = MCP 도구 1개** → 훅 없는 클라(Claude Desktop·Cline·Copilot·Continue)의 유일한 통로.
- **전송:** 로컬 stdio(MCP) + 로컬 HTTP(훅). 원격 동기화 필요 시 동일 코어를 Streamable HTTP로 게이트웨이화.

### 4) 정체성·UI — 클라 독립 "코치 창(HUD)"

대부분의 클라이언트는 풍부한 코칭을 자기 화면에 못 띄운다(훅 표시는 사실상 Claude Code뿐). 따라서 **우리만의 코치 창은 선택이 아니라 구조적 필연**이다. 어댑터가 어느 클라에서 데이터를 길어오든, 일관된 코칭을 그리는 곳 = 우리 창. 기존 Tauri 앱을 이 "코치 HUD"로 재정의한다.

UI 불변식(stance-lint로 강제):
- 코드 에디터 없음 (우리는 IDE가 아니다)
- AI 채팅 입력창 없음 (그건 AI 클라이언트다)
- 명령은 **"복사" 버튼만, "실행" 버튼 없음** (user-runs)

## 대안

### MCP 단독 (탈락)
- 장점: 전 클라이언트 호환, 표준 하나.
- 단점: 서버가 먼저 말 걸기 불가 → "턴 끝났으니 한마디" 능동 코칭 UX가 **구조적으로 불가능**. sampling 미구현으로 키 없는 조언 생성도 불가.

### 훅 단독 (탈락)
- 장점: 턴경계·사용자 표시 모두 네이티브.
- 단점: Claude Code·Cursor·Windsurf 3곳만. 나머지 클라 전부 버림. 클라마다 스키마가 달라 코어 없이는 중복 폭증.

### 옛 데스크톱 마법사 유지 (탈락)
- 장점: 이미 만들어짐.
- 단점: app-as-executor 그 자체. 테스트에서 가치 불명 문제를 일으킨 원흉. 스탠스 위반.

## 결과

### 좋은 점
- 정체성 확정: "AI 옆의 코치 레이어" — IDE도 채팅도 아님.
- 코어 1개 재사용 → 새 클라 지원은 얇은 어댑터 추가로 끝(확장성).
- 능동(훅)·수동(MCP) 양다리로 호환 범위 최대화.
- 규칙 기반 조언 → API 키 0, 어디서나 동작.
- 옛 Tauri 자산을 "코치 창"으로 재활용.

### 나쁜 점 / 트레이드오프
- 클라마다 훅 어댑터를 따로 유지(3종). Cursor 훅은 베타라 변동 추적 필요.
- 훅 없는 클라(Desktop·Copilot·Continue)는 능동 코칭 불가 → 수동(MCP)+코치 창으로만 보완.
- 규칙 기반 조언은 LLM 생성보다 유연성 낮음(향후 sampling 보급 시 재검토).
- 코치 창이라는 두 번째 표면 유지 비용.

### 후속 액션 (구현 단계)
1. `@tg/coach`를 **코어 + Claude Code 어댑터**로 분리 (정규화 입력 타입 도입).
2. 수동 조언 **MCP 도구 1개** 프로토타입 (전 클라 호환 검증).
3. **stance-lint** 가드레일 (app-as-executor 회귀 차단: 직접 실행·`additionalContext`·UI 실행버튼 금지).
4. **mock-scan** (가짜·강제·과도한 목업 탐지) 도입.
5. 코치 창(HUD) 와이어프레임 → Tauri 앱 재정의.
6. Cursor 어댑터 추가 (베타 스키마 대조).

### 영향
- v0.3 MCP-first 재설계의 *철학*을 구체화: 동반자 = 자동 실행기가 아니라 교육형 플로우 코치.
- 현재 데스크톱 앱의 온보딩 마법사·레시피 러너는 코치 창으로 재설계 대상이 됨.

## 보강 (2026-06-09): 도출형 조언 + 잘된-턴 발사 메커니즘

### 맥락 (실사용에서 드러난 두 문제)
1. **규칙으로 찍은 캔(canned) 격려·아이디어는 "뻔하고 늦다".** 예: 이미 다크모드를 구현한 프로젝트에 "다크모드를 추가하라"고 권하는 식 — 맥락 부재.
2. **에러 없이 잘된 턴에 코치가 사실만 띄우고 능동 제안이 없으면, 입문자는 "고장 났다"고 느낀다.** "잘됐으니 이것도·저것도 해봐"가 떠야 한다.

### 결정 A — 조언을 사실/주관 2층으로 분리
- **사실 버킷(recap/verify/do/missed/next) = 규칙.** 즉시·오프라인·환각 불가·일관됨.
- **주관 버킷(encourage/ideas) = 세션 AI가 실제 맥락으로 '도출'해 넘긴다(`DerivedAdvice`).**
  - `encourage`: 도출분 우선, 없으면 사실 기반 한 줄로 폴백.
  - `ideas`: 도출분만. **규칙 폴백 없음** — 모델이 안 쓰면 버킷이 안 뜬다(가짜 채움 금지).
- 코어가 가드레일을 건다: 명령 새치기·"제가 ~할게요"/"I'll add…"(한·영) 스탠스 누수 차단. 의심 시 '생략'(삭제 아님).

### 결정 B — 격려·아이디어 생성은 '사용자가 쓰는 그 세션 AI'로 (별도 API 금지)
| | A: 별도 AI API | **B: 세션 AI (채택)** |
|---|---|---|
| 비용 | 추가 과금 | **0** |
| 키 | 별도 키 필요(훅이 OAuth 못 읽음) | **불필요** |
| 프라이버시 | 트랜스크립트 외부 전송(새 노출면) | **새 노출 0(이미 세션 안)** |
| 맥락 | 2차 가공 | **실시간 전체 맥락** |

**B의 약점:** 세션 AI가 `coach_review`를 자호출하지 않으면 격려·아이디어가 안 뜬다.
**완충:** ① 사실층이 0초로 즉시 발사돼 침묵을 막는다 ② 안 부른 경우 사용자에게 "코치 봐줘" 수동 유도 1줄. 거짓 자동 약속은 하지 않는다.

### 결정 C — 발사 메커니즘 = '두 박자'
- **1박자(0초, 항상):** Stop 훅이 모델 호출 없이 사실 버킷을 `systemMessage`(사용자 전용)로 즉시 + HUD 상태파일 `phase='facts'`.
- **2박자(1~2초):** 살아 있는 세션 AI가 `coach_review`(MCP)를 자호출 → 맥락형 격려·아이디어 작성 → HUD를 `phase='enriched'`로 덧칠.
- **자동성은 '훅이 맥락을 작성'이 아니라 '사실층 즉시 보장 + 세션 AI가 도구를 자호출'로 달성.**
- 설치는 Stop 훅과 coach MCP(`tg-coach` 키, 기존 `tg` 백엔드와 분리)를 **한 쌍**으로 켠다 — 하나만 켜면 효과 0.

### 결정 D — locale 은 추측이 아니라 '선언 계약'
- 코칭 언어는 한글 비율 같은 휴리스틱으로 추측하지 않는다(혼합 스크립트 입문자 세션에서 진동). 세션 AI가 `locale`을 **선언**한다(`CoachReviewInput`/`AdviceOptions`, 기본 `'ko'`).
- **불변식:** 로케일 처리는 버킷을 삭제하지 못한다 — 언어만 바꾼다. 규칙 버킷은 현재 ko 전용(vibemate.kr 스탠스), 풀 번역 프레임워크는 도입 안 함(가짜 수요).

### 보류 (실측 게이트 뒤 — 블라인드 구현 금지)
- **`decision:block` 부스터(코드에서 제거됨, 2026-06-09 품질감사 결론):** 한때 훅이 세션을 한 번 더
  깨워 자호출을 유도하는 부스터를 옵트인(기본 OFF)으로 넣었으나, 7축 품질 감사에서 **ADR-0004 스탠스
  위반으로 확정**됐다 — 공식 문서상 `decision:block`의 `reason`은 **AI에게 주입**되므로 본질적으로
  컨텍스트 주입(AI 떠밀기)이고, 이는 우리 `stance-lint` `ai-push` 룰이 막는 게 맞다고 이미 결론낸 것이다.
  코드에 `stance-lint-allow`로 그 룰을 우회한 것은 문서와의 모순이었다. 또 `stop_hook_active`가
  **공식 문서에 의미 미정의**라 무한루프(최악의 고장) 위험까지 있었다. → **부스터 코드는 제거**하고,
  자호출 유도는 사용자에게 보내는 systemMessage 넛지(사람에게만)로만 남긴다. 재도입은 (1) 아래 실측으로
  자호출률이 낮다는 근거 + (2) 스탠스 모순 해소가 모두 충족될 때만.
- **훅 스키마 1회 실측**: `systemMessage` 전송 대상·`decision:block`·`stop_hook_active` 실재를 실제 런타임 JSON으로 확증(현재는 공식 문서 근거).
- **`turnId` 계약**: 현재 race 가드는 시간 창(60s) 휴리스틱. 정확한 단조 가드는 훅·MCP가 공유하는 `turnId`가 필요(미결).

### 구현 상태 (2026-06-09)
- P0(자동 경로 배선)·P1(원자적 상태·locale·폐기·가드) 구현·테스트 완료(`@tg/coach` 30 테스트 통과).
- P2는 코드 가능분(영어 스탠스 가드·locale 테스트·본 ADR)만 반영. 측정·실측은 보류, 부스터는 제거.
- 2026-06-09 7축 품질 감사: 부스터 제거 + server.ts 입력 크래시 가드 + state.ts NaN fail-safe +
  死익스포트 제거 + CoachState 타입 단일화(core/types.ts). 핵심 약속(enriched 자호출)은 여전히
  **미실측 의존**이므로 출시 전 자호출률 1회 실측이 게이트(docs/coach-self-invoke-measurement.md).
